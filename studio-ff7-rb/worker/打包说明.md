# 中文语音 MOD 打包说明

打包模式由用户每次明确指定，不替用户默认选择增量。不生成新语音、不调用 TTS/LLM。游戏仍选日语，使用同名 `zzz_cn_voice_*_P` 覆盖原中文包；`aa_cn_voice_edit_P` 只装字幕。

```bash
export PATH="$HOME/.dotnet:$PATH"
export DOTNET_ROOT="$HOME/.dotnet"
python3 studio-ff7-rb/worker/build_mod.py --full                # 用户要求全量时使用
python3 studio-ff7-rb/worker/build_mod_incremental.py           # 仅用户要求增量时使用
python3 studio-ff7-rb/worker/build_mod.py --incremental         # 与增量专用入口等价
python3 studio-ff7-rb/worker/build_mod.py --chapters 1,2         # 只声明本次章节范围
python3 studio-ff7-rb/worker/build_mod.py --jobs 4 --no-rsync    # 本机试包，不升级发布基线
python3 studio-ff7-rb/worker/build_mod.py --limit 10             # 只试前 10 条，强制不发布
```

`--full` 和 `--incremental` 互斥。无模式参数维持旧脚本的全量行为，仅为兼容；代理按用户指定选择入口。增量专用脚本拒绝 `--full`。显式增量遇到基线缺失/损坏、策略或范围不匹配时直接拒绝，保留旧包和旧基线；需要全量时必须由用户选择，不能静默转换。全量仍允许使用内容指纹一致的编码缓存。增量无变化时明确提示“不生成新 MOD”，不增加版本、不推进基线、不删旧包。`--jobs` 默认 4。

## 从哪一次时间开始算

以**上一次成功发布的打包开始快照**为基准，不以结束时间为准。每次先在同一个只读 REPEATABLE READ 语句中取得 MVCC 快照和数据库起点时间，读取选中版本与布局元数据，然后才校验旧包、冻结这些版本的音频字节。构建结束不重新查询数据库来“补记已完成”。快照之后改动的数据库选择和字幕留给下一次比较。音频在起点之后、冻结之前改变且无法取得起点字节时，本次立即拒绝并要求重试，不编码、不上传、不推进基线，也不丢弃锁定或改用原中文。冻结后再编辑音频时，本次继续使用已证明的冻结字节，下次比较会检测该编辑。

时间不是唯一筛选条件。比较锁定 ID、选择类型、字幕、音频 SHA256、源资产、切片/声道/战斗材料布局和构建策略。因此手动切回很早创建的旧版本、取消锁定、同一 ID 的文件被原地改写，仍能被发现。未锁定的生成候选不会进入音频构建。源游戏包和原中文包使用 SHA256；大文件的 SHA 可按 inode、大小、mtime、ctime 缓存，保留 mtime 的同大小编辑也会失效重算。

同一锁定资产的源布局、选择和音频指纹不变时，直接从已验证旧容器严格抽回原成品，不因为 `cache/` 被删除而把全部锁定语音重新编码。只改字幕时音频编码为 0，语音容器直接复用。

取消选择后恢复原中文资源；新增日文槽资源按原有完整打包语义重新组合，删除失效 alias。同 stem 的 EV/MV 分别使用自己的源头和 CID/路径，不能将 EV 字节塞进 MV。既有 `cn-original` 同 stem alias 的压缩流转移尚未实现，仍明确拒绝，不会用有损重编码冒充原字节。

## 完整包和变更清单

每份新目录都包含**本次声明范围内的完整、独立安装集**。没有变化的容器三件套从旧包校验后复制，字节保持一致；改变的容器从只读原中文包加上全部当前选中载荷重新组成，不依赖以前的增量链，也不会不断向旧容器追加死块。全部范围时包含九个原中文包；章节限定包不声明其他章节已经更新。

`manifest.json` 的 `incremental` 记录开始时间、上一个基线、变化/复用容器、变化 stem、需要删除的文件、实际编码事件、复用 chunk、输入指纹和待核对输入。`build-start.json` 保存精确选择和内容 SHA；`same_stem_aliases` / `same_stem_coverage` 保留 EV/MV 字节证明。`audio_encodes` 记录实际缓存未命中的编码次数；`rebuild_requested_chunks` 仅表示调用重建接口，可能命中编码缓存。

安装时先退出游戏，再按生成的 `安装说明.txt` 操作：

1. 初装可合并整份 `End`。已有上一版时，只覆盖 `changed_containers` 中各容器的 `.pak/.utoc/.ucas` 三件套；`reused_containers` 不需要重复制。
2. **执行 `deleted_files`（DELETE）清单，文件存在才删除。** 取消最后一条字幕或最后一个新增语音/alias 后，旧 `aa_cn_voice_edit_P` 或 `zzz_cn_voice_add_P` 必须移除，否则游戏还会播放旧资源。无可信历史的全量包也会列出缺席的可选包作为清理项。
3. 不要换成 `aa_` 或 `zzzz_` 语音叠包；删除以前遗留的 `zzzz_cn_voice_edit_P`。`aa_cn_voice_edit_P` 现在只用于字幕，按本次覆盖/删除清单处理。
4. 旧包不能藏在 `Paks` 子目录里，游戏也会扫描。未包含在本次范围中的普通 `zzz` 包保留；范围切换时，字幕/新增包对应本次范围，不能承诺保留其他范围的覆盖。

## 先确认新包，再删本机旧包

每次使用独立 `work/mod-build/日期/in-progress-随机ID/`，绝不在开包时删除已有 `staging`，同一天重复构建也互不覆盖。源资源若在构建期间改变则拒绝发布基线。

流程是：本地严格 Oodle 回读、期望字节比较和 Zen export 校验 → rsync 到共享盘新版本目录 → 比较本机与共享盘**完整文件清单和整文件 SHA256** → 本机目录改为 `verified-随机ID` → fsync + 原子替换 `work/mod-build/state/latest.json` → 删除上一份已验证本机目录。只删该已确认目录，不批量清理失败现场或保留区。

rsync 返回 0 不能单独作为成功依据。编码、回读、上传、共享盘 SHA 或源一致性失败，保留上一份包和原基线，失败目录单独留下。`--no-rsync`、`--limit` 均不推进发布基线，不删旧包。新基线指向新完整包，旧本机包删除后仍能继续增量。

共享盘 `/srv/backups/ff7-backup/rebirth/mod/日期/版本` 的历史版本永远不由脚本删除。当天版本仍为 0–4，已创建但失败的版本目录留作检查。`state/` 位于日期目录之外；状态只有 JSON，不储存额外音频副本。构建进程锁防止两个新脚本同时推进基线。

## 旧版全量包：一次性初始化

旧版脚本产物如需接入增量，必须先完成全量构建并核对无误；不要在构建期间替换运行源码或初始化状态。由负责该次构建的主流程使用真实起点证据初始化。初始化工具默认只读 dry-run，既不查当前数据库，也不启动打包或上传。

```bash
python3 studio-ff7-rb/worker/bootstrap_mod_state.py \
  --project-root /srv/ff7-sound \
  --output /实际已核验的本次本机目录 \
  --share /实际对应共享盘目录 \
  --receipt work/mod-build-run-20261102/build-start.json \
  --locked-snapshot work/mod-build-run-20261102/locked-before-build.json \
  --builder-before work/mod-build-run-20261102/build_mod.before-incremental.py \
  --audio-evidence work/mod-build-run-20261102/bootstrap-audio-evidence.json \
  --metadata-evidence work/mod-build-run-20261102/bootstrap-metadata-evidence.json
# 仅在当前全量完成、输出与共享盘最终核验通过后，重复相同命令并加 --apply。
```

工具核对真实 receipt 的源码 SHA 和锁定数量、共享盘/本机文件 SHA、全部资产严格回读和 Zen、同 stem CID/路径/SHA 证明。`--apply` 还会拒绝仍在运行的原打包进程，并拒绝覆盖已有状态。

初始化使用**开包前**选中快照和真实开始时间。普通中文锁定资产需用源字节、选中音频和内容键缓存证明产物；alias 还需对照本次 manifest 的实际音频、源和成品 SHA。开始后变动或无法证明的输入记为 dirty，不把当前数据库全部锁定误算进旧包。

补充证据必须与真实起点和 13473 个 start IDs 精确对应。工具核对音频 SHA/stat/稳定性和起点前时间、元数据更新时间、旧源码 SHA，并用实际游戏源和旧强内容键缓存与发布 CID/路径/载荷字节比对。根据这些历史字段重建 JP-only 切片、战斗材料组，保存与新 writer 相同的指纹。证据缺失可只证明普通资产；未证明的条目仍保持 dirty，证据矛盾则拒绝。不能省略补充证据后声称所有类型已证明。

初始化后首次显式增量会完整核对，不直接走“无变化”快退；已证明的普通音频、alias、JP-only 切片和战斗库均可从发布包复用，删除编码缓存也无需重编码这些 chunk。只有父流程在真实包上 dry-run、应用初始化并运行首次显式增量后，才能宣称实际零编码；隔离副本只提供离线回归证据。选择身份仅包含有效锁定选择及相关布局/字幕，未锁定文本和生成候选不制造全量 changed_stems；新增锁定、取消选择及游戏源内容改变仍参与比较。首次核对发布后记录完整新输入指纹。

Linux 严格校验不等于 Win11 游戏启动验证；manifest 继续如实保留 `game_launch_tested: false`。

## 多声道过场（2026-11-07）

标记 `multichannel_review_required` 的MV对白使用独立的全对白声道覆盖策略，防止中心已中文但左右/环绕仍播日文。它核对原Voice事件和原WAV SHA，以真实下一发声为界保留未选原声；重叠片段必须有该句/源SHA/精确区间的明确选择记录。中心采用已锁音频，左右/环绕按原能量比分布中文；日文混响被移除，不声称还原原混响。LFE及窗口外在HCA编码前逐采样保留，整bank HCA重编码后的误差另做真实回读验证。完整约束见 `../../studio-common/docs/movie-surround-packing.md`。普通/旧切片编码缓存继续沿原身份，新增渲染计划不复用旧中心声道成品。

### 独立伴随轨字幕

封包时统一丢弃 `line_meta.extra.dual_speaker.main_stem` 关联的独立伴随轨字幕覆盖；即使界面误保存了 `subtitle_text` 也不写入游戏字幕。主轨字幕照常处理，伴随轨音频选择和数据库记录保持原样。清单 `companion_subtitles_suppressed` 记录被抑制的条目。增量制作也会移除旧包中这类字幕覆盖，无需重编码音频。
