# 假名时长加权设计

目标：用本项目日语原声估计摩拉的相对时长，运行时只查小表，不调用大模型、不增加 TTS 次数。2026-10-09 实现阶段为校准工具及中性计算接入，尚未取得逐摩拉标注数据；正式比值不使用未经验证的权重。

## 表的单位

按实际读音的完整摩拉计，不按字形或元音一刀切。きゃ 为一个键；っ、ん、ー 各自独立；标点、空白不入表。おう、えい 等拼写先保持两个普通摩拉，缺少词边界及发音信息时不猜长音。未知键回退 1.0。暂不量化成快中慢三档，避免损失校准信息。

初版候选权重限制在 0.85–1.15，向 1.0 收缩；这是工程约束，不是语言学测量结论。清化不等于删去一拍，不因元音听不见直接扣半拍。字幕换行仍不算停顿，整句尾标点仍免费。

## 样本和校准

从原始日语音频取样，覆盖主角及不同场景。不能用拉伸后的中文 TTS 校准。现有 jp_speech_s 包含句中停顿，只可用于整句对照，不能冒充逐摩拉标注。

先进行日语音素强制对齐，合并成摩拉，并抽听校验边界。去除静音、笑声、气声及明显拖腔；句末延长的摩拉单独标记，在基础假名权重训练时排除。必须保留场景、角色、原文件及标注来源以追溯。对齐器及其模型选型属于采样阶段，当前脚本不假装自动产生真实时间边界。

校准工具接受 JSON 数组，每句包含 stem、scene、split（train/test）和 segments（kana、duration_s）。kana 使用平假名；每句至少五个有效摩拉。不同 split 不允许同一场景，stem 不得重复。可在本机 work/ 保存数据，不提交音频。

每句以其中摩拉时长中位数归一，尽量移除整句快慢影响。每类默认至少 30 个训练观测；不足仍为 1.0。按类取相对时长中位数、收缩和限幅。测试集只评估、不拟合；报告按句平均的相对摩拉时长绝对误差，和全部权重为 1 的基线比较。

```bash
python3 studio-ff7-rb/worker/mora_weights.py \
  work/mora-aligned.json work/mora-weight-report.json
python3 -m unittest discover -s studio-ff7-rb/worker -p 'test_mora_weights.py'
```

工具输出始终是 experimental，productionApproved=false。一次误差降低不足以自动发布：还要检查不同角色、场景是否普遍改善，利用独立原声测试完整句子的时长预测（语速基准只能从训练集取得，去掉实测静音），并检查异常台词的试听结果。不能只报告参与拟合样本的成绩。若无稳定增益，保留等权计算。

## 接入和正式启用

共享核心返回原始 mora，同时增加 weightedMora 和 weightStatus。当前 weightStatus=uncalibrated，全部权重 1.0；units、normalizedRatio、数据库筛选、改写门槛保持当前线上算法。实验计算函数可接受候选表，生产服务暂不从环境或文件偷偷加载它。

验证通过后，发布固定的权重文件和样本报告，使用“加权摩拉 + 句中标点 × 1.5”作为日文 units。保留原始 mora 用于解释；界面及改写提示明确显示加权拍，不能仍把整数摩拉当总拍数。读音分歧保持待核对；后续还应检查两个读音虽拍数相同但加权结果不同的情况。

启用时必须一并更新 Python 和网站的 BEAT_VERSION，重算 SQL 缓存，并重新校准日中归一除数，防止整张权重表的尺度变化误当成语速改善。当前代码线上除数为 1.33（见 PROGRESS 2026-10-08），用户提供的 AGENTS 仍记为 1.20；此实验不顺带改动除数，正式发布时需明确统一口径。报警及自动处理仍读 normalizedRatio，0.7–1.3 范围不自动处理、改写目标 0.9–1.1 的策略独立于权重。

发布后先做只读差异报告，检查跨越自动处理阈值的台词，再用于新批次；既有锁定、试听、字幕、历史 journal 不追改。回滚需同时回滚权重、除数和版本并刷新缓存。
