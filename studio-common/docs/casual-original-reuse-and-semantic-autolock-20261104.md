# 普通原稿复用与改稿强语义自动锁定

2026-11-04 最新用户规则：先调试完整当前非演出闭环，源码/测试/部署通过后只运行**原200条中当前UI“改”的固定子集**（本轮只读冻结为16条）。不是全库生成，也不对已锁、异、新或清单外条目追加运行；全库匿名、缺稿采纳、唱歌方案继续debug_only。实际开跑由主任务部署并给ROOT READY之后执行，本实现阶段零业务POST、未改既有锁。

用户同时明确：**改稿也可锁，前提语义、核字、实际时长全部严格通过**。这覆盖此前改稿一律候选的旧规则。99%是愿景，不能放宽门禁凑锁定率。

## 同一新run优先救旧原稿

`POST /api/lines/{stem}/auto-run` 新增受控 `reuseOriginalCandidates:true`，只接受显式 `forceGenerate:true` 的非演出台词；默认false，scene/mixed拒绝该选项。普通三次原稿、之后最多三批三条的原生预算不变。复用复制/对齐/编辑不算新TTS，也不额外造run。

候选必须同stem、ready、candidate、独立安全WAV路径，spoken完整正文和game_zh快照都与当前原稿一致（只忽略P/S/空白、不NFKC）。不能是JP锁、改稿、半成品或已人选，不能删改原稿唯一问意标记。旧组内原稿子候选不会因parent_tts_id而被漏掉；排序显式使用数据库数值id。

发音规则也是准入证据：当前reference词库渲染的实际发送稿必须等于源可追溯的 `tts_text_sent`。例如原文仍为“陆号”，当前发送“六号”而旧源发送“陆号”，必须拒绝旧源并继续新制作；不能凭ASR还是同一汉字猜旧声音正确。命中当前末级tts_pinyin/手工注音会改变载荷时，旧源若无匹配最终载荷证据也不复用，不伪造旧规则指纹。

当前cleanup有JP保留片段时，旧完整音频/旧正文必须有闭合的正文提取来源链才能复用。首版保守记明确拒绝原因，继续新TTS正文流程；绝不把旧cleanup正文半成品当完整原稿。拒绝复用不等于排除目标。

通过准入的源在台词→新run→人工状态→源版本事务锁内重新核当前原文、原字幕、源路径/字节SHA与当前发音规则，再复制为属于新run的独立文件，记录 `operation=casual-original-reuse`、source_id/source_run_id/源SHA。源旧run、旧文件、字幕、状态和父子关系不改。新副本不继承旧ASR或semantic_review，随后执行同一真按钮对齐→新核字→必要页面“发”区间≤10%缩放→新核字。任一通过即停止，不再发新TTS；否则才继续正常原稿三次/改稿三选一。

6475“不痛不痒”已独立CPU和获批单次新核字证明可由真按钮救回；这不等于修改6475旧记录或将旧核字套给新字节。新的受控任务仍复制独立副本并按实际文件执行核字。

## 强语义与实义读音门禁

`casual-semantic-review.ts` 保留原稿、完整成稿和问号，不能compact之后抹去问意。原稿真实阶段或可信复用原稿，只有正文/完整恢复内容/问意不变，且实际ASR逐字或明确词库对应、无读音疑点才快通。改稿阶段即使字数/汉字相同或只改问号，也必须独立Grok终审。

终审输入绑定当前中文原稿与正文、真实候选稿/完整恢复稿、可信JP与可靠配对EN、可用邻句、当前角色名/发音表、保留段分离信息、实际新ASR、读音疑点和音频SHA。模型只看这些证据，不能声称听到了音色或音频。

严格JSON包含 faithful、readingEquivalent、needsHuman、readingUncertain、hardReadingRisk、negationChanged、questionChanged、entityChanged、三个实义风险数组和证据reason。缺字段/格式错、需人审、低确定性或实质风险均拒绝。否定、条件、限定、对象、姓名与有义问句不能被缩稿抹去；只有原稿/可靠语境可唯一恢复同一主客体、条件动作不变时，才允许中文自然代词省略和条件压缩。例如“敢动的话我就开枪！”→“敢动就开枪！”可保义；换成我敢动或别人开枪不可。脚本缺义与ASR读音风险分开记录。

“只能→是能”“干劲来了→赶紧来啦”等实义近音不因原稿未改或核字宽容就快锁。低确定性仅记风险，不声称音频确实错；原稿读音风险只同稿有限重试，不能删改原文遮掩。模型可以独立确认equivalent且无hard风险，届时仍须其它所有门禁通过。

语义失败在原有最多三轮改稿预算内反馈，允许同字数或恢复必要词，不强制越改越短到一字。语义修复时字数建议至少允许恢复原稿必要词；全程仍以真实成品时长核字验收。已明确被拒绝的“够/句够”不能因为短就成为推荐成品；失败兜底优先语义已证完整但时长未合格者，未知/被拒语义不冒充通过。

## 最终强绑定与自动锁

真按钮使用当前JP正文PCM开口与实际slot；按“发”缩放保留中文首尾PCM，只缩首声至末声span，句中停顿包含。JP拟声/环境/语气片段预算预扣、原速原长原PCM最后拼回。正文10总/9发/1静最多缩至9.1总，最终含所有保留片段的总长仍≤完整JP，绝不assembly后整体stretch。

每个对齐/压缩新文件重新ASR，审稿绑定原稿、完整成稿、实际ASR、读音信息和核字文件SHA。组装副本还记录审过的正文SHA与最终完整音频SHA。复制/派生时不继承源版本semantic_review。组装保存事务会再核正文源文件SHA和字幕，不能在读取后等待锁期间被同路径替换而继续。

最终FOR UPDATE严格比较保存/审稿时预期字幕原字符串，人工仅删问号、挪问号、改逗号也必须停止；同时重验当前原稿、成稿、音频SHA、语义证据和完整字幕问意一致。已有人锁/异常、原文/字幕/源字节变化均整项停止且无其它候选兜底。不能“run passed但字幕/语义绑定不够所以未锁”。

原稿和改稿只有核字、强语义/读音、实际完整时长、组件PCM、当前原稿/成稿/字幕/SHA绑定**全部严格通过**才自动locked。未通过保留独立历史与明确失败理由，不假锁、不覆盖人选。

## 服务端能力与恢复

GET/POST `/auto-run` 均返回顶层 `reuse_original_candidates_supported:true` 和 `semantic_autolock_supported:true`，调度器必须拒绝旧镜像静默忽略选项。客户端可提供8–128字符的字母数字/`_.:-` requestId，新run与 `auto-run-request` 事件同事务提交；payload使用camelCase requestId、reuseOriginalCandidates、forceGenerate、semanticAutoLock。POST仍返回正式run id，执行由同一run继续，便于未知响应时只读恢复，不盲重发。
