## 每个候选共用的自然时长处理

原稿和改稿后每条都走同一函数链：必要的清理正文格式规范化 → 中文正文首尾保守裁边 → 保存独立派生 → 对实际保存字节重新核字 → 必要时正文最多10%保调缩短 → 对缩短新文件重新核字 → 从最终通过版本中择优。处理失败保留原文件，不能当通过候选。没有原声首尾清理时，原生PCM16采样率在裁边阶段保持；既有RubberBand压缩仍以24k单声道输入运行，并对新文件核字。

`trimCasualBodyEdges` 直接分析中文正文原始PCM，取各声道绝对幅度最大值。5%峰值强信号边界加两端40ms只是候选，最终必须向外扩到覆盖全部0.1%峰值弱信号及两端2ms保护；低音量时门槛最低1LSB。拟删除区不包含达到弱信号阈值的PCM。强信号活动不足20ms、全零或孤立尖峰不裁，小于5ms的单侧裁量不处理。保留区按PCM字节复制，不浮点重编码，不移动句中停顿、不按JP开口对齐、不补长静音。证据不充分时原字节no-op，由后续真实核字/时长判定，不能把阴性检查当成功。

有裁边才生成 `conversion_meta.operation=casual-body-edge-trim` 独立版本，记录 `source_id`、源/裁后SHA及 `edge_trim` 的原帧、输出帧、边界、阈值、保护量和实际秒数。保存前在既有台词/任务/版本事务锁内复核人工状态、源字幕与源SHA。最终无论是否清理回拼，都再校对被选实际文件与其核字SHA；人工改字幕/源字节等 `CasualInterventionError` 会停止整项且无候选兜底，不能换选另一条绕过干预。

日文保留首尾不参与中文裁边或压缩，最后仍是原JP首段PCM＋完整核字的中文正文PCM＋原JP尾段PCM。回拼成品另存，保留原声精确PCM与总长上限保护。

## 次数与择优

原稿逐次请求一条，最多三次，任何一次经过处理、核字及允许的正文缩短通过即停，不调用压稿模型。三次耗尽后，只有完整读出且实际超长的候选可作为压稿依据；压缩后漏读不能用于删稿，但仍保存的原始完整超长读音可作为合法反馈证据。使用该证据前再次核对对应文件SHA。

之后最多三轮反馈，每轮原生请求三条；全部返回者逐条完整验收，包括裁边、新核字和必要缩短后的新核字。只返回一或两条也可从真实成功者中选；某条DSP失败不丢弃兄弟候选，人工/源干预仍停止整项。改稿后全漏读只同稿重试，不借删字掩盖漏读。

最多原生请求为 `3 + 3×3 = 12`，仍受整轮全局24条持久额度约束，派生编辑不占原生额度。clone 新增 `candidateCount`，只接受已验证归属与stage1的非场景自动请求设为1或3；手动或场景请求不能改计数。该参数与 `feedbackRound` 时间行为独立，普通批量三条仍使用自然时长，不启用场景layout/Seed/拍数/分段对口型。场景和手动原生计数策略不变。

择优先淘汰核字、处理或时长未通过者，再按读音疑点少、派生处理少、变速少与稳定生成顺序排序。不把越短或越贴近日文总长当质量目标，不调用额外Grok排序，也不声称程序听到了音色质量。日志按候选记录 `casual-candidate-align` → `casual-duration-attempt` → 可选压缩及新核字 → `casual-candidate-pick`，保存读音疑点与处理依据。

原稿正文严格未改（仅忽略标点/符号/空白、不NFKC）、实际最终核字和时长通过、字幕沿用原稿时仍直接自动锁定，包括原稿第二/第三次、裁边和允许缩短。改稿成品保留候选；显式人工复核的改稿/失败沿用原状态规则。人工选择优先。
