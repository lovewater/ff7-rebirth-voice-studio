# 普通音频的保守原声清理与回拼

2026-11-04 用户确认：普通音频不要求对口型，允许程序保守分离拟声、语气及独立原声；用处理后的参考音频和正文做TTS，最后合回原声。已接入两站公共程序，不自动发起业务生成。

## 范围与处理顺序

接入 `runCasualDuration`：field普通对话、现有自然时长斜体入口、显式field/unknown普通复核。scene/mixed的Seed场景流程及普通入口旧unknown分支保持原路由，不把战斗声库按是否有字幕推断为field。

1. 检查人工选择，唱歌/整句纯语气沿原分流。原JP采用可寻址文件解码，避免MP3管道尾填充放宽总长。精确全零PCM直接按原字节锁JP、保留原字幕，不要求存在CN，不ASR/TTS、不将静音长度当有效预算。
2. Qwen-ASR指定Japanese并开启ForcedAligner，取得全文与秒时间轴。分类只用本地规则，不调用Seed或文本大模型。
3. 保守检查首尾可分离声音；字轴、原稿或波形证据不足就保留完整参考和原中文稿。句中声音暂不猜跨语言插入位置。
4. 只有提出清理时，提取参考并再用纯Qwen-ASR复听一次；与清理后的日文正文在全半角/假名、标点空白归一后必须严格一致。失败、漏词、服务异常均整条退回原音、原稿、原预算。
5. 采用清理时保存独立参考WAV，将清理后的中文稿及实际 `promptPath/preservePromptAudio` 传给所有TTS轮次。运行记录登记真实参考路径和正文，清空旧 `reference_seed_asr`，不会把Qwen证据塞成Seed缓存。
6. 正文预算为完整JP实际帧数减去保留首尾帧数。仍是原稿一次加最多三次反馈，中文正文独立核字；field/显式普通复核允许仅正文最多10%保调缩短并对新文件重新核字，仍超长才由Grok压稿。斜体沿用其既有自然时长和压稿规则，不新增分段口型或整体缩放原声。
7. 将原prefix、实际核字的正文WAV、原suffix按顺序拼成独立最终版本，不补时间槽，不强行保持尾声原毫秒位置。最终实测总长不得超过完整JP（1ms采样容差）。原声与已验证正文均直接复制PCM字节，不做浮点重编码；只可能缩短的是独立中文正文派生版本。

## 保守规则

- 仅极小兼容词表，例如独立啊/哦/嗯、重复笑声。中日两端须有可对应的独立文本，才同时删各自原前后缀；保留所有正文原字，不按字数估切点。`はい/よし/なるほど/ねえ`等有具体词义的日语不当成可复用原声。
- 文字和字轴必须闭合；非Japanese、空识别、错误状态、零宽、重叠、倒序或越界轴均不切。强制对齐不证明文字确实被读出。
- 使用至少250ms持续低能量区间，字轴两侧各留80ms保护。阈值是局部工程证据，不把低音量当成原本无声。
- 字轴外首尾声音仍叫“未分类原声”，不冒充声音事件识别。只有可靠官方JP来源且全文闭合才允许提取；Remake的ASR补字标记直接否决此权限，来源不明也默认不允许。
- 中文端已有未配对的独立语气/咳嗽等文字时，拒绝该端未分类提取，避免保留原声后再TTS双读；无标点或括号形式同样可以阻断，但不会据此猜删中文。
- 清理后正文参考必须有实际PCM活动，拒绝全零或孤立尖峰；按正文局部峰值判断，保留相对响边缘很弱的真实正文。

## 字幕、核字与人工优先

TTS正文和最终回拼版本分别保存。正文字幕明确只覆盖本轮正文；最终用程序恢复已配对删除的原中文前后缀。正文未改时，最终字幕完全沿用原游戏字幕，清空覆盖。

field自动锁定仍要求完整正文与原文严格一致（仅忽略标点/符号/空白，不NFKC）、核字及最终总长通过、字幕沿原文。新回拼成品还记录正文ASR输入SHA及原声PCM验证，不能仅恢复一个全文字符串冒充核字通过。改稿或未通过结果继续人工处理。

核字绑定真正发给ASR的同一份音频字节SHA；回拼重读正文不匹配则停止。人工改正文字幕未锁时，也在组装前及保存事务内锁定源版本后两次核对预期字幕；不重算NULL绕过人工编辑。人工锁定/异常始终优先。

组装失败、预算耗尽、缺失文件等不会把未回拼正文推荐成完整成品；原始候选及派生文件仍保留供复核。斜体收尾的保护使用lines→run→versions一致锁顺序，scene默认行为不改。
